# История изменений Runvoice

История выпусков, исследований и проверок хранится в этом файле.
Актуальные инструкции — в [руководстве](README.md), [архитектуре](docs/architecture.md),
[тест-плане](docs/testing.md) и [каталоге скриншотов](docs/screenshots/README.md).

Материалы проверок сохраняют контекст соответствующих сборок, включая ограничения,
ошибки и ожидания того времени. Даты внутри отчётов относятся к проведённым проверкам;
они не означают дату публикации релиза. Отчёты разных сборок не заменяют текущий тест-план.

## Не выпущено

### Документация

- История и результаты проверок объединены в CHANGELOG.md; остальные Markdown-файлы описывают текущее состояние.
- Тест-план организован по действующим функциям, документ архитектуры выделен отдельно.
- Инструкции согласованы с текущими вкладками настроек, CGEventTap, нативной записью, позиционированием HUD и правилами подписи; имена артефактов используют метаданные вместо фиксированного номера.
- В бэклоге оставлены только нерешённые задачи; правила ведения документации закреплены в AGENTS.md.
- Снимки настроек пересняты; история на изображении заполнена демонстрационными данными, описан изолированный запуск для публикации снимков.

### 33. Частота подтверждённого предпросмотра Whisper — 1.1.11

Сначала ищется продолжение относительно конца опубликованного текста в двух
последовательных гипотезах. Длинное совпадение в более ранней части окна не
задерживает совпавшие новые слова. При ненадёжной привязке сохраняются прежние
защиты и восстановление после разрыва окна. Ранний первый отклик, фильтрация
мусора и подтверждение на паузе сохранены; неподтверждённый хвост не добавлен.

Окно 6 с, первый запрос после 0.8 с и порог 0.6 с нового аудио сохранены.
Таймер проверяет готовность каждые 100 мс; после ответа проверка выполняется сразу.
Одновременно работает один запрос, выбирается свежий снимок, очереди нет.
При ошибке повтор ограничен паузой не меньше секунды. Новых настроек нет.

| ID | Сценарий | Ожидание | Тип |
|---|---|---|---|
| Pace1 | Длинный старый общий префикс, меняющееся слово перед стабильным хвостом | Новое продолжение публикуется после второго совпавшего ответа | A |
| Pace2 | Русский, английский, русский с Cypress/GitHub Actions | Новые подтверждённые слова появляются, ранее опубликованные сохраняются | A/M |
| Pace3 | Расхождение внутри нового продолжения | Публикация останавливается перед спорным словом до его подтверждения | A |
| Pace4 | Несколько аудиофрагментов накопились во время запроса | Следующий запрос идёт сразу после ответа и содержит самый свежий снимок | A |
| Pace5 | Нового аудио нет / длинная тишина | Нет лишних запросов, допускается одно подтверждение на паузе | A |
| Pace6 | Отмена в callback, остановка, новая сессия, поздний ответ | Следующий запрос не запускается; старые события не меняют новую сессию | A/M |
| Pace7 | HTTP-ошибка при коротком таймере | Нет потока повторов, после паузы запросы возобновляются | A |

| Pace9 | Одинаковая запись длиннее минуты до/после | Сравнены первый отклик, медиана/p95/max интервалов, число запросов и CPU-время сервера | A |
| Pace10 | HUD, многоточие, 1/3/10 строк, остановка и финальная вставка | Прежний лимит строк и позиция, итоговое распознавание не использует preview | A/M |

подпись не меняется между пересборками, и macOS **не сбрасывает Accessibility**.

Если сертификата нет, `build-app.sh` подпишет ad-hoc — тогда после каждой
пересборки разрешение придётся выдавать заново.

### 32. Маркер скрытого начала предпросмотра — 1.1.10

Если начало предварительного текста не помещается в выбранное число строк,
видимый фрагмент начинается с `... `. Префикс измеряется вместе с текстом;
при нехватке места удаляются слова с начала, последние слова сохраняются.
Для длинных токенов без пробелов обрезка сохраняет целые символы Unicode.
Текст привязки хранится отдельно от отображаемого маркера. Префикс не добавляется
в исходную гипотезу, финальное распознавание, вставку, буфер или историю.

### FR-002 — Завершать запись нажатием Enter

**Статус:** `In progress`, реализация 1.1.8, проверяется.
**Дата:** 2026-11-12

#### Согласованное поведение

Во вкладке «Хоткеи» добавлен отключаемый флажок
«Останавливать распознавание по нажатию Enter». По умолчанию выключен,
применяется после сохранения без перезапуска. Старые settings.json без
`stopRecordingOnEnter` также получают false. Сброс вкладки выключает функцию.

Return (36) и Enter цифрового блока (76) без модификаторов завершают только
активную запись. Они запускают существующий `stop()` — финализацию WAV,
Whisper/завершение потока Nemotron, AI и вставку. Это не отмена записи.

Поглощается одно физическое нажатие: keyDown, его autorepeat и keyUp, даже если
запись уже остановлена. Новые нажатия после отпускания сразу работают обычно,
в том числе во время финального распознавания. Блокировки до вставки нет.
Shift/Control/Option/Command+Enter и режим назначения хоткеев сохранены.

#### Реализация и защита от гонок

`DictationKeyPolicy` хранит только захваченные коды клавиш и принимает решение
пропустить событие, поглотить, завершить или отменить конкретную сессию. Потерянный keyUp
не блокирует следующий свежий keyDown. Политика сохраняется при обновлении tap,
чтобы завершить уже захваченное физическое нажатие после сохранения настроек.

`HotkeyMonitor` слушает keyDown/keyUp, но основные хоткеи вызывает только на keyDown.
Для Enter он получает актуальный recordingSessionID из DictationSession,
передаёт его в отложенный callback. `finishRecording(expectedSessionID:)`
проверяет фазу и UUID перед вызовом существующего stop(), не вызывает toggle().
Запоздавшее событие не может начать или завершить другую запись.

Автоматические проверки используют синтетические события без установки tap,
публикации клавиш в систему или отправки сообщений в реальный чат.
Матрица регрессии и результаты — docs/testing.md, раздел 30.
Для реального перехвата нужен работающий CGEventTap с существующим Accessibility.

### 23. Проверка микрофона и падение AVAudioIOUnit — 1.1.1

Причина и исправление:

- В crash reports `Runvoice-2026-11-12-125833*.ips`, `125840.ips`, `130019.ips`
  зафиксирован EXC_BAD_ACCESS в `AVAudioIOUnit::IOUnitPropertyListener` одновременно
  с `AVAudioEngine dealloc` из `NativeAudioRecorder.stop`.
- Любое AVAudioEngineConfigurationChange ошибочно считалось потерей устройства.
  После исправления времени жизни AVAudioEngine аппаратный прогон выявил, что
  запуск мог завершаться успешно без поступления PCM (20 из 20 пустых записей).
- Захват переведён на отдельный входной AUHAL с выключенным выходом по Apple TN2091.
  Unit сохраняется между сессиями. Остановка I/O и снятие callback происходят
  до освобождения контекста, PCM дренируется перед завершением.

  первого. Параллельные stop дренируют файл один раз.

### Исследование подходов VoiceInk

Runvoice 1.1.1 требует macOS 15+. Реализация написана в Runvoice самостоятельно;
исходные файлы VoiceInk не переносились. В качестве отдельной зависимости используется
[FluidAudio](https://github.com/FluidInference/FluidAudio), revision
`ee78635d23d52379117554ba72358b65a0612447` из исследованной версии VoiceInk.
Лицензии FluidAudio и fastcluster включаются в arm64-бандл.

| Подход | Реализация Runvoice |
|---|---|
| Нативный захват вместо отдельного FFmpeg | входной AUHAL с выключенным выходом, выбор Core Audio input по UID, пул буферов; файловый I/O и ресемплинг в отдельной очереди |
| Один источник аудио | Из одного PCM идут WAV, уровень микрофона и ASR; второй микрофон для эквалайзера не открывается |
| Распознавание во время записи | Nemotron Multilingual, полный словарь multilingual, фрагменты 1120 мс, FluidAudio / Core ML |
| Сохранение модели в памяти | Помощник RunvoiceASR остаётся запущенным между диктовками; Whisper держит свой сервер |
| Словарь терминов | Prompt Whisper, decode-time bias Nemotron и предпочтительные написания в AI-промпте |
| Полноценный прогрев | Синтетическая речь при старте, сохранении и пробуждении; без истории и вставки |
| Быстрое завершение | Немедленная остановка preview, дренирование записанных буферов и конвертера; finish потока вместо повторного полного ASR |
| Резервный результат | При ошибке / пустом результате / таймауте потока весь WAV обрабатывает выбранный Whisper |

Используется [Nemotron 3.5 ASR Streaming Multilingual 0.6B Core ML](https://huggingface.co/FluidInference/Nemotron-3.5-ASR-Streaming-Multilingual-0.6b-CoreML).
Всегда загружается вариант `multilingual/1120ms`, включая русский и английский;
выбор English не заменяет его вариантом Latin с урезанным словарём.
Модели загружаются отдельно от приложения. Установочный маркер публикуется после
успешной загрузки Core ML. Повторная проверка/скачивание и отмена доступны в настройках.

На Intel остаётся Whisper на CPU. Whisper пока работает через встроенный сервер:
переход на прямой C API не входил в эти изменения. Его preview остаётся ограниченным
окном последних шести секунд, а итоговый проход охватывает всю запись. Частичные
Whisper-гипотезы не используются как окончательный текст.

Профиль AI и выбранный Whisper автоматически не меняются. Новый движок и словарь
выбираются пользователем. Нативный WAV и временный текст удаляются после обработки
или отмены. Финальное распознавание и постобработка по-прежнему выполняются
последовательно: время ответа AI входит в задержку до вставки.

Протокол проверок и ограничения — [testing.md](#22-нативный-аудиотракт-и-потоковый-движок--12-ноября-2026).

В 1.1.1 AVAudioEngine заменён входным AUHAL: аппаратная регрессия выявила
пустые записи и падение AVAudioIOUnit при освобождении движка. Повторные проверки
микрофона выполняются на настоящем устройстве через `--test-microphone`.

### FR-001 — Диаризация: подписывать реплики «Говорящий 1..N»

**Статус:** `Proposed` (не реализовано, ждёт приоритета)  
**Дата:** 2026-10-20

#### Запрос

Если в записи участвует несколько собеседников, распознавать это и подписывать
реплики:

```text
Говорящий 1: Привет, как дела?
Говорящий 2: Хорошо, спасибо. А у тебя?
```

Имена — «Говорящий 1», «Говорящий 2» и т.д. Если говорящий один, метки не нужны.
При постобработке метки должны сохраняться.

#### Что проверили в whisper.cpp 1.9.5

- `--diarize` — **стерео-диаризация**. Нужен 2-канальный файл, где говорящие
  разведены по каналам. Внутри сравнивается энергия каналов, в текст добавляется
  `(speaker 0)` / `(speaker 1)`. Максимум 2 говорящих, только стерео.
- `--tinydiarize` — определяет **смену говорящего**, но не личность. Требует
  специальную модель `tdrz`, доступную только для английского. Имён не выдаёт.
- Полноценной диаризации «моно-запись, N говорящих, русский» в whisper.cpp нет.
- Приложение пишет моно 16 кГц, поэтому встроенный `--diarize` не даст меток.

#### Предлагаемое решение

Интегрировать offline-диаризацию через **sherpa-onnx**:

- сегментация pyannote + speaker embeddings;
- работает с моно, русским языком и N говорящими;
- выдаёт временные отрезки с ID говорящих;
- сегменты Whisper (с таймкодами) сопоставляются с отрезками диаризации;
- метки «Говорящий 1..N» нумеруются по первому появлению;
- при одном говорящем метки не добавляются.

Изменения в приложении:

- настройка **«Разделять говорящих»** (по умолчанию выключена);
- выбор количества: **авто / 2 / 3 / 4**;
- скачивание моделей диаризации (~30–50 МБ) в общий менеджер моделей;
- при включении — запрос Whisper с таймкодами (`verbose_json`), отдельный шаг
  диаризации и склейка;
- HUD-состояние «Определяю говорящих…»;
- промпт: сохранять метки, не менять номера, не объединять реплики и не
  придумывать новых говорящих;
- `docs/testing.md`: новые сценарии (моно/стерео, 1/2/3 говорящих, русский,
  пересекающаяся речь, Intel/Apple Silicon).

#### Альтернативы

1. **Стерео, 2 говорящих** — встроенный `--diarize`; быстро и без новых моделей,
   но нужен стерео-вход и максимум 2 собеседника.
2. **Tinydiarize** — только смена реплик, английский, без имён.
3. **Только промпт** — сохранять готовые метки, если они уже есть в тексте, но
   не определять говорящих.

#### Критерии готовности

- [ ] Настройка включения/выключения диаризации.
- [ ] Поддержка моно-записи с обычного микрофона.
- [ ] Русский язык.
- [ ] 2–4 говорящих (минимум), номера по первому появлению.
- [ ] Один говорящий — без меток.
- [ ] Промпт сохраняет метки и не смешивает реплики.
- [ ] Работает на macOS 15+ (arm64 и Intel).
- [ ] Обработка не ломает обычную диктовку при выключенной настройке.
- [ ] Сценарии добавлены в `docs/testing.md`.

#### Риски

- Размер моделей и бинарника; для Intel — дополнительная сборка.
- Дополнительные 2–10 секунд обработки.
- Пересекающаяся речь и шум ухудшают качество кластеризации.
- Число говорящих может определяться неверно; нужен ручной выбор 2/3/4.
- Модели диаризации нужно скачивать и проверять по SHA-256.

обновить статус на `Planned` и добавить тестовые сценарии.

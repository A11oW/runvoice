# История изменений Runvoice

История выпусков, исследований и проверок хранится в этом файле.
Актуальные инструкции — в [руководстве](README.md), [архитектуре](docs/architecture.md),
[тест-плане](docs/testing.md) и [каталоге скриншотов](docs/screenshots/README.md).

Материалы проверок сохраняют контекст соответствующих сборок, включая ограничения,
ошибки и ожидания того времени. Даты внутри отчётов относятся к проведённым проверкам;
они не означают дату публикации релиза. Отчёты разных сборок не заменяют текущий тест-план.

## Не выпущено

### Фильтр аудио и независимый словарь API

- Добавлены включённые по умолчанию фильтр RMS/Silero VAD и использование словаря API, регулируемый порог −70…−20 dBFS (начальный −55). Настройки применяются к следующим запросам после сохранения; API-вкладка прокручивается.
- Отдельный статический CPU-помощник VAD для arm64/Intel использует штатную модель без скачивания. Входы независимы, данные передаются по ограниченному IPC без временных WAV. Проверяются речь и 80 мс громкости выше порога; сохраняются внутренние паузы и края по 200 мс. Пропуск даёт пустой 200 без ASR/AI, ошибка — 503. Повторная VAD-обрезка в Whisper отключается только в запросах API с общим фильтром.
- Выключение словаря очищает только API-проекцию для ASR и автоматически добавленной части AI-промпта. Сохранение только API-параметров выделено в отдельный путь без общего callback, перенастройки хоткеев/HUD, прогрева диктовки, изменений Keychain, автозапуска и истории; остальные поля на диске не нормализуются.
- Обновлены текущие инструкции, архитектура и регрессионные сценарии фильтрации, словаря и изоляции сохранения.
- Итоговые проверки: 93 API-проверки arm64 и 91 под Rosetta, включая отсев без вызова ASR/AI, ошибку VAD, порог и сохранность словаря диктовки; 155 UI-проверок, в том числе отдельный callback API-only и сохранение остальных полей без нормализации. Прошли 205 нативных, 444 live preview/геометрии, 35 pause/resume preview, четыре handoff, 47 редактирования и 176 паузы/WAV.
- Реальная ASR-проба Whisper Q5 и Nemotron с общим фильтром, синтетическим WAV и независимыми параллельными сессиями прошла. Настоящий VAD обеих архитектур прошёл 18 проверок: тишина, слабый шум, щелчок, обычная/ослабленная речь, речь с паузами, тишина после речи и синтетические «да/нет». Это не оценка живой встречи или всех тембров; пользовательский микрофон не включался, новые веса не скачивались.
- Визуальная проверка обнаружила проблемы раскладки и обрезки прокрутки API: добавлена проверка видимости элементов, задана обрезка по границам вкладки. Финальный снимок проверен на минимальном размере окна; --snapshot и --snapshot-states завершились. Обновлены восемь Markdown-файлов, проверены 91 локальная ссылка/изображение и 562 сценария.
- Собраны обе архитектуры и DMG с сохранением номера подготовки. Подписи ad-hoc, архитектуры и macOS 15 у исполняемых компонентов, отсутствие Homebrew-зависимостей, VAD, hdiutil verify, SHA-256 и совпадение файлов внутри смонтированных только для чтения образов проверены. Developer ID и нотаризации нет. Установленное приложение, пользовательские настройки и ktalk-assist не заменялись. Изоляция во время живой записи и физический Intel остаются ручной проверкой. Логи — `.build/api-filter/`, реальная ASR-проба — `.build/local-api/real/benchmark.json`.

### Независимая модель распознавания API

- Во вкладке API добавлен выпадающий список: «Как в приложении» либо отдельная скачанная Whisper/совместимая FluidAudio. Список использует каталог раздела «Распознавание» и обновляется после изменения установленных моделей; скачивания из API нет.
- Выбор сохраняется отдельно, старые настройки наследуют модель приложения. API может использовать другую модель и технологию, сохраняя общие язык и словарь; диктовка не меняется. Текущий запрос завершает работу со своим снимком, следующие получают новый выбор после сохранения.
- Удалённая модель остаётся недоступным сохранённым пунктом; health и запросы возвращают 503 без автоматической подмены. Alias runvoice-active и адрес сервиса сохраняются, health показывает эффективную модель API. Сервис работает вместе с приложением.
- Обновлены текущие инструкции, архитектура и сценарии проверки независимого выбора, совместимости, переключения и удаления модели.
- Итоговые проверки: 76 API-проверок на arm64 и 74 на x86_64 под Rosetta, включая настоящий клиент ktalk-assist; 150 проверок настроек/UI. Проверены миграция, сохранение, каталог скачанных моделей, несовместимая архитектура, независимые Q5/Q8 на подставном ASR, смена выбора во время запроса, отображение фактически загруженной модели, 503 при удалении и работа после восстановления файла.
- Настоящие Whisper Large v3 Turbo Q5_0 и Nemotron прошли пробу с синтетическим WAV: явная модель API использовалась при другой технологии в настройках приложения, прямое/API-распознавание и независимые параллельные сессии работали. Весов Q8 на машине нет; реальное распознавание Q8 не проверялось и новые веса не скачивались. Полная регрессия arm64: 205 нативных проверок, 444 live preview/геометрии, 35 pause/resume preview, четыре handoff, 47 редактирования и 176 паузы/WAV. Явный список исходников нативного тестового сборщика дополнен новым типом настроек.
- Собраны обе архитектуры и DMG с сохранением номера подготовки; VAD включена. Подписи приложений и приложений внутри образов, архитектуры, отсутствие Homebrew-зависимостей, совпадение бинарников/метаданных/VAD, hdiutil verify и SHA-256 проверены. Подпись ad-hoc; Developer ID и нотаризации нет. Штатные --snapshot и --snapshot-states завершились, вкладка API переснята и визуально проверена на минимальном размере окна. Проверены восемь Markdown-файлов, 91 локальная ссылка/изображение и 556 сценариев. Логи — `.build/api-model-selection/`, реальная ASR-проба — `.build/local-api/real/benchmark.json`. Установленное приложение, пользовательские настройки и ktalk-assist не изменялись; физический Intel и живая встреча отдельно не проверялись.

### Локальный API для приложений встреч

- Добавлены вкладка «API», отдельное включение сервиса и AI-правки (оба выключены по умолчанию), порт 8790, копирование адреса и состояние выбранной технологии/модели. Настройки применяются после сохранения и не меняют AI-режим обычной диктовки.
- Loopback POST `/runvoice/v1/audio/transcriptions` принимает multipart WAV PCM16/16 кГц/моно, model=runvoice-active и response_format=json; возвращает JSON text. Добавлен health. Подтверждена совместимость существующей transcribeService из ktalk-assist без правок соседнего проекта.
- API использует сохранённые технологию, модель, язык и словарь в независимом прогретом движке: приватный Whisper-server на 8798 либо собственный FluidAudio worker. Смена настроек применяется к следующим задачам, текущая сохраняет профиль; недоступный движок даёт ошибку без замены технологии.
- Одна задача выполняется, до восьми ожидают; тело ограничено 1 МиБ, загрузка — 10 с, общий deadline с очередью/AI — 85 с. Отмена клиента и остановка сервиса очищают только API-задачи и временные файлы. GUI, микрофон, вставка, status и история диктовки не используются.
- AI использует общий промпт диктовки со словарём и снимком ключа. Добавлена отмена HTTP/CLI и параллельное чтение pipe OpenCode; подробные журналы API-правки отключены, ошибки обобщены. Origin и некорректные HTTP/multipart/WAV отклоняются.
- Добавлены протокольные/интеграционные тесты API, реальные ASR-пробы и сценарии текущего тест-плана; документация описывает подключение ktalk-assist и ограничения сервиса.
- Итоговая регрессия arm64: 205 проверок нативного аудиотракта; 444 live preview/геометрии, 35 pause/resume preview и четыре handoff; 47 редактирования; 143 настроек/HUD; 176 паузы/WAV; 46 HTTP/API. На x86_64 под Rosetta прошли те же 46 API-проверок, архитектура тестового бинарника подтверждена. Проверены настоящий клиент ktalk-assist, очередь/429, отмена/504, смена профиля, конфликт порта, AI-ветка и отсутствие приватного тела AI-ошибки в журнале.
- UI-регрессия обнаружила локализованное отображение порта как «8 790»; поле переведено на строку без разделителей, итоговый тест и снимок показывают адрес с 8790. Вкладки и документация пересняты с API, в том числе FluidAudio и резервная модель; восемь Markdown-файлов, 91 локальная ссылка/изображение и 551 сценарий проверены.
- На синтетической русской речи 7.039 с выполнены по десять прогретых сравнений прямого вызова ASR-адаптера и полного HTTP API без AI. Whisper Large v3 Turbo Q5_0: медиана 538/519 мс (прямой/API), эмпирический p95 570/669 мс. Nemotron Multilingual: медиана 106/106 мс, p95 113/108 мс. Меньшая медиана API не объявляется ускорением: серия мала и отражает разброс. Перед серией выполнены дополнительные запросы прогрева; системные кэши уже прогреты. Старт API-worker до ready составил 883 мс для Whisper и 420 мс для Nemotron, это не оценка первого запуска на чистой машине.
- Реальная параллельная работа двух независимых сессий Whisper и Nemotron прошла. Остальные FluidAudio-модели без локальных весов, живая встреча, физический Intel и внешние AI-провайдеры отдельно не проверялись. Пользовательский микрофон не включался, веса не скачивались, ktalk-assist и его конфигурация не изменялись. Подробные отчёты — `.build/local-api/real/benchmark.json` и `.build/local-api/`.
- Собраны arm64, x86_64, host-копия, оба DMG и SHA-256 с сохранением номера текущей подготовки. Проверены версии, архитектуры, подписи ad-hoc, отсутствие Homebrew-зависимостей и локальных сэмплов, hdiutil verify и контрольные суммы. Подписи и совпадение бинарников/метаданных проверены внутри смонтированных только для чтения DMG. Developer ID и нотаризации нет. Установленное приложение и сохранённые настройки пользователя не заменялись; API по умолчанию выключен.

### Скрытая модалка аудиосэмплов

- Запись сэмпла и открытие папки убраны из «Основных». Четыре последовательных клика по версии внизу настроек открывают одну модалку «Аудиосэмплы»; подсчёт серии использует AppKit.
- В модалке доступны запись/остановка, открытие папки и выбор другой папки с сохранением выбора. При записи видны красный индикатор, секунды и стандартный эквалайзер от реального PCM; смена папки блокируется до окончания сохранения. Закрытие завершает и сохраняет запись.
- Папка внутри Git исключается адресным экранированным правилом, корень репозитория и .git не допускаются. Можно выбрать папку вне проекта. Исходный WAV, JSON, автостоп и отсутствие ASR/AI сохраняются.
- Штатный рендер настроек дополнен состояниями скрытой модалки и записи с демонстрационными уровнями без микрофона; обновлены текущие инструкции и сценарии проверки.
- Регрессия обнаружила и устранила незавершающийся обход родительских каталогов при выборе папки вне Git; обход ограничен числом компонентов пути и использует строковый родительский путь. Итоговый прогон прошёл: 141 проверка настроек/HUD/сэмплов и 176 проверок паузы/WAV. Подтверждены четвёртый клик, отсутствие действий в «Основных», один sheet, выбранная папка, таймер, передача PCM в эквалайзер и сохранение при закрытии. Физический микрофон не использовался.
- Обе архитектуры и DMG пересобраны; подписи приложений, `hdiutil verify` и SHA-256 проходят. `--snapshot` и `--snapshot-states` прошли на arm64; переснят экран «Основные», добавлены два снимка модалки. Проверены восемь Markdown-файлов, 89 локальных ссылок/изображений и 538 сценариев. Логи — `.build/sample-modal/`. Версия подготовки сохранена; установленное приложение не заменялось.

### Независимая аура и настройка по сэмплам

- По уточнению пользователя убраны сглаживание и затухание правого эквалайзера: `WaveformView` снова принимает каждый текущий кадр сразу, без таймера и изменения исходной чувствительности. Огибающая 100/320 мс перенесена исключительно в кнопку записи.
- Программно проанализированы два локальных WAV: RMS, пики, клиппинг, распределения спектральных уровней и отклик старой/новой ауры. Диапазон ауры подобран по этим данным: среднее шести полос, порог 0.04, коэффициент 2, ограничение 0.88. В повторном прогоне сэмплов новая аура не достигала насыщения.
- Аудио и подробные результаты остаются вне Git; локальные отчёты и программа анализа — `.build/aura-calibration/`. ASR, AI и преобразование исходных сэмплов не выполнялись.
- На arm64 прошли 444 проверки live preview/геометрии, 35 pause/resume preview, четыре handoff и 123 проверки настроек/HUD/сэмплов. Добавлены независимые проверки мгновенного сброса эквалайзера и продолжающегося спада ауры, порога фона и ограничения расширения.
- Собраны обе архитектуры и DMG, проверены подписи приложений, `hdiutil verify` и SHA-256. Встроенные `--snapshot-states` и `--snapshot` прошли на arm64; обновлены 11 снимков HUD. Проверены восемь Markdown-файлов, 87 локальных ссылок/изображений и 535 сценариев. Живой микрофон не включался, установленное приложение не заменялось.

### Сдержанная пульсация и локальные сэмплы голоса

- Снижена чувствительность ауры: вместо sqrt/нелинейного усиления трёх пиков используется среднее шести полос с порогом фона, максимальный отклик ограничен. Уменьшена непрозрачность; спектр и аура получили общую огибающую с нарастанием 100 мс и спадом 320 мс вместо резких вспышек.
- Во вкладку «Основные» добавлены «Запись сэмпла», «Остановить и сохранить» и «Папка сэмплов». Запись выбранного микрофона ограничена минутой и сохраняется также при закрытии окна; одновременный захват с диктовкой/проверкой блокируется.
- WAV PCM16/16 кГц/моно сохраняется без ASR, VAD, AI, нормализации, вставки и истории. В соседний JSON записываются длительность, RMS/пик dBFS, процентили, клиппинг и временная шкала кадров 64 мс.
- Локальная папка `local-audio-samples/` исключена из Git и упаковки; если исходники по месту сборки недоступны, можно выбрать корень проекта. Добавлены сценарии проверки и регрессия сохранения исходных отсчётов/метрик.
- Проверены 440 сценариев live preview/геометрии, 35 pause/resume preview и четыре handoff, 123 проверки настроек/HUD/сэмплов, 176 проверок паузы/WAV. Сэмпл в автоматизации записывался подставным источником: исходные отсчёты, длительность, RMS/пик, кадры JSON, повторный стоп, удаление неуспешной записи и отсутствие дублей правила Git подтверждены. Физический микрофон для сэмпла не включался.
- Обе архитектуры и DMG пересобраны с сохранением номера подготовки текущего выпуска; подписи приложений, `hdiutil verify` и SHA-256 проходят. Штатные снимки настроек и 22 состояний HUD получены на arm64; обновлены вкладка «Основные» и 11 изображений HUD. Проверены восемь Markdown-файлов, 87 локальных ссылок/изображений и 534 сценария. Логи — `.build/sample-recording/`; установленное приложение не заменялось.

## [1.1.14]

### Пауза диктовки и кнопки HUD

- Пауза и продолжение доступны по Space (отключается в «Хоткеях») и первой кнопке HUD. На паузе микрофон остановлен; сохраняются сессия, WAV и позиция карточки, таймер считает только активную запись. Основной хоткей и включённый Enter завершают запись, стоп и включённый Esc отменяют её.
- После паузы оконные модели распознают полный снимок записанного аудио до её границы. Whisper использует полный контекст, beam 5 и 0.5 с завершающей тишины только в запросе. Полный ответ заменяет неполный preview; при ошибке допускаются два повтора. Nemotron сохраняет текст завершённых отрезков для продолжения и финального результата.
- Кнопка записи показывает красную точку и заполненную ауру, синхронизированную со спектром. Отклик на обычный голос усилен; наведение плавно превращает круг в штрихи паузы за 180 мс и сохраняет реакцию на звук. Пауза отключает ауру. Кнопки не забирают фокус.
- Исправлена доставка коротких PCM-буферов до границы паузы. Обновлены инструкции, тестовые сценарии и скриншоты записи, наведения, перехода, паузы и продолжения.
- Номер выпуска приведён к следующему после опубликованного `1.1.13`. Номера `1.1.15`–`1.1.17` ниже относились к неопубликованным локальным итерациям и не обозначают релизы GitHub.

### FR-002 — Завершать запись нажатием Enter

**Статус:** `In progress`, реализация 1.1.8, проверяется.
**Дата:** 2026-11-12

#### Согласованное поведение

Во вкладке «Хоткеи» добавлен отключаемый флажок
«Останавливать распознавание по нажатию Enter». По умолчанию выключен,
применяется после сохранения без перезапуска. Старые settings.json без
`stopRecordingOnEnter` также получают false. Сброс вкладки выключает функцию.

Return (36) и Enter цифрового блока (76) без модификаторов завершают только
активную запись. Они запускают существующий `stop()` — финализацию WAV,
Whisper/завершение потока Nemotron, AI и вставку. Это не отмена записи.

Поглощается одно физическое нажатие: keyDown, его autorepeat и keyUp, даже если
запись уже остановлена. Новые нажатия после отпускания сразу работают обычно,
в том числе во время финального распознавания. Блокировки до вставки нет.
Shift/Control/Option/Command+Enter и режим назначения хоткеев сохранены.

#### Реализация и защита от гонок

`DictationKeyPolicy` хранит только захваченные коды клавиш и принимает решение
пропустить событие, поглотить, завершить или отменить конкретную сессию. Потерянный keyUp
не блокирует следующий свежий keyDown. Политика сохраняется при обновлении tap,
чтобы завершить уже захваченное физическое нажатие после сохранения настроек.

`HotkeyMonitor` слушает keyDown/keyUp, но основные хоткеи вызывает только на keyDown.
Для Enter он получает актуальный recordingSessionID из DictationSession,
передаёт его в отложенный callback. `finishRecording(expectedSessionID:)`
проверяет фазу и UUID перед вызовом существующего stop(), не вызывает toggle().

### Исследование подходов VoiceInk

Runvoice 1.1.1 требует macOS 15+. Реализация написана в Runvoice самостоятельно;
исходные файлы VoiceInk не переносились. В качестве отдельной зависимости используется
[FluidAudio](https://github.com/FluidInference/FluidAudio), revision
`ee78635d23d52379117554ba72358b65a0612447` из исследованной версии VoiceInk.
Лицензии FluidAudio и fastcluster включаются в arm64-бандл.

| Подход | Реализация Runvoice |
|---|---|
| Нативный захват вместо отдельного FFmpeg | входной AUHAL с выключенным выходом, выбор Core Audio input по UID, пул буферов; файловый I/O и ресемплинг в отдельной очереди |
| Один источник аудио | Из одного PCM идут WAV, уровень микрофона и ASR; второй микрофон для эквалайзера не открывается |
| Распознавание во время записи | Nemotron Multilingual, полный словарь multilingual, фрагменты 1120 мс, FluidAudio / Core ML |
| Сохранение модели в памяти | Помощник RunvoiceASR остаётся запущенным между диктовками; Whisper держит свой сервер |
| Словарь терминов | Prompt Whisper, decode-time bias Nemotron и предпочтительные написания в AI-промпте |
| Полноценный прогрев | Синтетическая речь при старте, сохранении и пробуждении; без истории и вставки |
| Быстрое завершение | Немедленная остановка preview, дренирование записанных буферов и конвертера; finish потока вместо повторного полного ASR |
| Резервный результат | При ошибке / пустом результате / таймауте потока весь WAV обрабатывает выбранный Whisper |

Используется [Nemotron 3.5 ASR Streaming Multilingual 0.6B Core ML](https://huggingface.co/FluidInference/Nemotron-3.5-ASR-Streaming-Multilingual-0.6b-CoreML).
Всегда загружается вариант `multilingual/1120ms`, включая русский и английский;
выбор English не заменяет его вариантом Latin с урезанным словарём.
Модели загружаются отдельно от приложения. Установочный маркер публикуется после
успешной загрузки Core ML. Повторная проверка/скачивание и отмена доступны в настройках.

На Intel остаётся Whisper на CPU. Whisper пока работает через встроенный сервер:
переход на прямой C API не входил в эти изменения. Его preview остаётся ограниченным
окном последних шести секунд, а итоговый проход охватывает всю запись. Частичные
Whisper-гипотезы не используются как окончательный текст.

Профиль AI и выбранный Whisper автоматически не меняются. Новый движок и словарь
выбираются пользователем. Нативный WAV и временный текст удаляются после обработки
или отмены. Финальное распознавание и постобработка по-прежнему выполняются
последовательно: время ответа AI входит в задержку до вставки.

Протокол проверок и ограничения — [testing.md](#22-нативный-аудиотракт-и-потоковый-движок--12-ноября-2026).

В 1.1.1 AVAudioEngine заменён входным AUHAL: аппаратная регрессия выявила
пустые записи и падение AVAudioIOUnit при освобождении движка. Повторные проверки
микрофона выполняются на настоящем устройстве через `--test-microphone`.

### FR-001 — Диаризация: подписывать реплики «Говорящий 1..N»

**Статус:** `Proposed` (не реализовано, ждёт приоритета)  
**Дата:** 2026-10-20

#### Запрос

Если в записи участвует несколько собеседников, распознавать это и подписывать
реплики:

```text
Говорящий 1: Привет, как дела?
```

Имена — «Говорящий 1», «Говорящий 2» и т.д. Если говорящий один, метки не нужны.

#### Что проверили в whisper.cpp 1.9.5

- `--diarize` — **стерео-диаризация**. Нужен 2-канальный файл, где говорящие
  разведены по каналам. Внутри сравнивается энергия каналов, в текст добавляется
  `(speaker 0)` / `(speaker 1)`. Максимум 2 говорящих, только стерео.
- `--tinydiarize` — определяет **смену говорящего**, но не личность. Требует
  специальную модель `tdrz`, доступную только для английского. Имён не выдаёт.
- Полноценной диаризации «моно-запись, N говорящих, русский» в whisper.cpp нет.
- Приложение пишет моно 16 кГц, поэтому встроенный `--diarize` не даст меток.

#### Предлагаемое решение

Интегрировать offline-диаризацию через **sherpa-onnx**:

- сегментация pyannote + speaker embeddings;
- работает с моно, русским языком и N говорящими;
- выдаёт временные отрезки с ID говорящих;
- сегменты Whisper (с таймкодами) сопоставляются с отрезками диаризации;
- метки «Говорящий 1..N» нумеруются по первому появлению;
- при одном говорящем метки не добавляются.

Изменения в приложении:

- настройка **«Разделять говорящих»** (по умолчанию выключена);
- выбор количества: **авто / 2 / 3 / 4**;
- скачивание моделей диаризации (~30–50 МБ) в общий менеджер моделей;
- при включении — запрос Whisper с таймкодами (`verbose_json`), отдельный шаг
  диаризации и склейка;
- HUD-состояние «Определяю говорящих…»;
- промпт: сохранять метки, не менять номера, не объединять реплики и не
  придумывать новых говорящих;
- `docs/testing.md`: новые сценарии (моно/стерео, 1/2/3 говорящих, русский,
  пересекающаяся речь, Intel/Apple Silicon).

#### Альтернативы

1. **Стерео, 2 говорящих** — встроенный `--diarize`; быстро и без новых моделей,
   но нужен стерео-вход и максимум 2 собеседника.
2. **Tinydiarize** — только смена реплик, английский, без имён.
3. **Только промпт** — сохранять готовые метки, если они уже есть в тексте, но
   не определять говорящих.

#### Критерии готовности

- [ ] Настройка включения/выключения диаризации.
- [ ] Поддержка моно-записи с обычного микрофона.
- [ ] Русский язык.
- [ ] 2–4 говорящих (минимум), номера по первому появлению.
- [ ] Один говорящий — без меток.
- [ ] Промпт сохраняет метки и не смешивает реплики.
- [ ] Работает на macOS 15+ (arm64 и Intel).
- [ ] Обработка не ломает обычную диктовку при выключенной настройке.
- [ ] Сценарии добавлены в `docs/testing.md`.

#### Риски

- Размер моделей и бинарника; для Intel — дополнительная сборка.
- Дополнительные 2–10 секунд обработки.
- Пересекающаяся речь и шум ухудшают качество кластеризации.
- Число говорящих может определяться неверно; нужен ручной выбор 2/3/4.
- Модели диаризации нужно скачивать и проверять по SHA-256.

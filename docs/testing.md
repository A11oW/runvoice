# Тестирование Runvoice

> **Правило проекта:** при любом изменении функционала этот документ обновляется
> вместе с кодом. Новые настройки, состояния, ошибки и исправленные баги должны
> получить сценарий (или быть добавлены в существующий).

Документ описывает тестовые сценарии приложения: сборку, установку, первый запуск,
хоткеи, диктовку, HUD, настройки, модели, постобработку и краевые случаи.

## 1. Область и подход

- Приложение: menu-bar приложение Runvoice для macOS.
- Распознавание: встроенный `whisper-server`/`whisper-cli`; на Apple Silicon также
  Nemotron Multilingual через помощник FluidAudio / Core ML. Модель выбирает пользователь.
- AI-провайдеры: профили OpenCode, OpenAI-совместимого и Anthropic-совместимого
  API; для диктовки и улучшения профиль выбирается отдельно.
- Проверки делятся на **автоматизированные** (команды в терминале) и **ручные**
  (звук, фокус, разрешения, несколько приложений).
- Полный прогон выполняется перед релизом; smoke-набор — после каждой сборки.

## 2. Матрица окружений

| Параметр | Значения |
|---|---|
| macOS | 15.x и новее |
| Процессор | Apple Silicon (arm64), Intel (x86_64) |
| Экран | встроенный с вырезом, внешний, несколько мониторов |
| Раскладка | русская, английская, переключение источника ввода |
| Микрофон | встроенный, USB, Bluetooth |
| Приложения для вставки | TextEdit, Safari/Chrome, Terminal, VS Code, Slack |
| Сеть | онлайн, офлайн, медленная, неверный API URL |
| Разрешения | выданы, не выданы, сброшены через TCC |
| Установка | чистая машина, поверх старой версии, старый CLI-режим |

## 3. Приоритеты и типы

- **P0** — блокирует релиз: приложение не ставится/не запускается, диктовка или
  вставка не работают, модель не скачивается.
- **P1** — важные функции и типовые ошибки.
- **P2** — полировка, редкие комбинации, совместимость.
- **A** — автоматизировано, **M** — вручную.

Автоматическая регрессия нового HUD и предпросмотра: `make test-live-hud`.
Проверяет границы экранов и фиксированную позицию, WAV/PCM, передачу языка,
короткий preview, отмену, новую сессию, ошибки сервера, снимок буфера обмена,
финальный shell→app handoff и отсутствие pbcopy/pbpaste в нём. Не использует
микрофон, общий пользовательский буфер и реальные AI-провайдеры. Тест временного
NSPasteboard требует доступа к службе буфера macOS; ручные проверки фокуса,
каретки, диктовки и Space остаются обязательными.

## 8.5. Улучшение выделенного текста

Функция: выделить текст в любом редакторе → **⌥⌘E** → модель улучшает его по
отдельному промпту → текст заменяется на месте. Провайдер и модель выбираются
отдельно для улучшения в «Постобработке», а профили настраиваются в
«Провайдерах»; история распознаваний не пополняется.

## 19. Что требует отдельного тестового хука

Эти сценарии сложно воспроизвести без имитации:

- неверная SHA-256 при загрузке модели (подменить файл/каталог);
- нехватка места на диске (нужен образ/квота);
- повреждённый `settings.json` (ручная порча файла);
- падение `whisper-server` в середине запроса (kill в нужный момент);
- Gatekeeper на чистой машине (нужна вторая машина/VM);
- Intel без Rosetta (нужна реальная Intel-машина).

Для улучшения текста fallback-ветку (⌘C/⌘V) можно проверить без Electron:

```sh
open -n -a /Applications/Runvoice.app --args --force-improve-clipboard
```

В этом режиме приложение не использует AX для чтения/замены выделения, а всегда
идёт через буфер обмена. Обычный запуск флаг не использует.

Для них в идеале добавить debug-флаги (`--simulate-...`) или отдельные фикстуры.

## 23. Проверка микрофона и падение AVAudioIOUnit — 1.1.1

Причина и исправление:

- В crash reports `Runvoice-2026-11-12-125833*.ips`, `125840.ips`, `130019.ips`
  зафиксирован EXC_BAD_ACCESS в `AVAudioIOUnit::IOUnitPropertyListener` одновременно
  с `AVAudioEngine dealloc` из `NativeAudioRecorder.stop`.
- Любое AVAudioEngineConfigurationChange ошибочно считалось потерей устройства.
  После исправления времени жизни AVAudioEngine аппаратный прогон выявил, что
  запуск мог завершаться успешно без поступления PCM (20 из 20 пустых записей).
- Захват переведён на отдельный входной AUHAL с выключенным выходом по Apple TN2091.
  Unit сохраняется между сессиями. Остановка I/O и снятие callback происходят
  до освобождения контекста, PCM дренируется перед завершением.
- Проверка и диктовка имеют один lease; второй захват получает busy без изменения
  первого. Параллельные stop дренируют файл один раз.
- Устройство выбирается по стабильному UID; старые настройки по имени мигрируют
  при сохранении. Отсутствующий UID не заменяется устройством по умолчанию.
- Проверка отклоняет пустой PCM, отдельно сообщает об отказе разрешения. Низкий
  уровень реального сигнала продолжает показываться как «тишина» оранжевым.

## 26. Минималистичный HUD — 1.1.4

## 27. Залитые иконки, центровка и текущий спектр — 1.1.5

Статусные иконки и кнопка остановки — залитые круги с символом просветом.
Вырезание ограничено отдельным графическим слоем, поэтому фон карточки не удаляется.
Нативная иконка приложения-получателя сохранена. Иконки, подпись, таймер и спектр
имеют общий центр строки; высота системных подписей определяется их fittingSize,
а не фиксированным смещением на 12 pt.

из существующего PCM16/16 kHz преобразуются Accelerate DFT с окном Hann;

без бегущей строки, сдвига или следа старых полос. Тишина обнуляет текущий кадр.

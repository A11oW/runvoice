# Тестирование Runvoice

> **Правило проекта:** при любом изменении функционала этот документ обновляется
> вместе с кодом. Новые настройки, состояния, ошибки и исправленные баги должны
> получить сценарий (или быть добавлены в существующий).

Документ описывает тестовые сценарии приложения: сборку, установку, первый запуск,
хоткеи, диктовку, HUD, настройки, модели, постобработку и краевые случаи.

## 1. Область и подход

- Приложение: menu-bar приложение Runvoice для macOS.
- Распознавание: встроенный `whisper-server`/`whisper-cli`, модель выбирается пользователем.
- Постобработка: OpenCode, прямой OpenAI-совместимый API или без правки.
- Проверки делятся на **автоматизированные** (команды в терминале) и **ручные**
  (звук, фокус, разрешения, несколько приложений).
- Полный прогон выполняется перед релизом; smoke-набор — после каждой сборки.

## 2. Матрица окружений

| Параметр | Значения |
|---|---|
| macOS | 13.x, 14.x, 15.x |
| Процессор | Apple Silicon (arm64), Intel (x86_64) |
| Экран | встроенный с вырезом, внешний, несколько мониторов |
| Раскладка | русская, английская, переключение источника ввода |
| Микрофон | встроенный, USB, Bluetooth |
| Приложения для вставки | TextEdit, Safari/Chrome, Terminal, VS Code, Slack |
| Сеть | онлайн, офлайн, медленная, неверный API URL |
| Разрешения | выданы, не выданы, сброшены через TCC |
| Установка | чистая машина, поверх старой версии, старый CLI-режим |

## 3. Приоритеты и типы

- **P0** — блокирует релиз: приложение не ставится/не запускается, диктовка или
  вставка не работают, модель не скачивается.
- **P1** — важные функции и типовые ошибки.
- **P2** — полировка, редкие комбинации, совместимость.
- **A** — автоматизировано, **M** — вручную.

## 16. Автоматизированные проверки

```sh
# синтаксис скрипта
bash -n bin/dictate.sh

# сборка и установка (host)
make app
make install-app

# две архитектуры
lipo -info dist/Runvoice-arm64.app/Contents/MacOS/Runvoice
lipo -info dist/Runvoice-intel.app/Contents/MacOS/Runvoice

# минимальная версия
otool -arch arm64 -l dist/Runvoice-arm64.app/Contents/MacOS/Runvoice | grep -A3 LC_BUILD_VERSION
otool -arch x86_64 -l dist/Runvoice-intel.app/Contents/MacOS/Runvoice | grep -A3 LC_BUILD_VERSION

codesign --verify --deep --strict dist/Runvoice-arm64.app
codesign --verify --deep --strict dist/Runvoice-intel.app

# DMG
make dmg
hdiutil verify dist/Runvoice-1.0.0-arm64.dmg
hdiutil verify dist/Runvoice-1.0.0-intel.dmg
shasum -a 256 -c dist/Runvoice-1.0.0-arm64.dmg.sha256
shasum -a 256 -c dist/Runvoice-1.0.0-intel.dmg.sha256

# HUD/настройки без Screen Recording
/Applications/Runvoice.app/Contents/MacOS/Runvoice --snapshot-states
/Applications/Runvoice.app/Contents/MacOS/Runvoice --snapshot

# Intel-срез под Rosetta (на Apple Silicon)
arch -x86_64 dist/Runvoice-intel.app/Contents/MacOS/Runvoice --snapshot-states
arch -x86_64 dist/Runvoice-intel.app/Contents/Resources/whisper/bin/whisper-server --help
```

## 19. Что требует отдельного тестового хука

Эти сценарии сложно воспроизвести без имитации:

- неверная SHA-256 при загрузке модели (подменить файл/каталог);
- нехватка места на диске (нужен образ/квота);
- повреждённый `settings.json` (ручная порча файла);
- падение `whisper-server` в середине запроса (kill в нужный момент);
- Gatekeeper на чистой машине (нужна вторая машина/VM);
- Intel без Rosetta (нужна реальная Intel-машина).

Для них в идеале добавить debug-флаги (`--simulate-...`) или отдельные фикстуры.

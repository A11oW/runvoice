# Архитектура Runvoice

Runvoice — приложение строки меню для macOS 15 и новее. Apple Silicon использует
Whisper с Metal, а также Nemotron, Parakeet и Phonon через FluidAudio / Core ML;
Intel использует Whisper на CPU. В настройках сначала выбирается технология,
затем совместимая модель; язык, предпросмотр и AI-профили задаются отдельно.

Основной каталог не смешивает технологии. Резервный Whisper для FluidAudio
настраивается в отдельной sheet-панели: «Готово» переносит черновик в основное
окно, «Отмена» откатывает его; сохранение JSON выполняется основной кнопкой
«Сохранить». Загрузка файлов выполняется сразу. Нескачанные FluidAudio-модели
нельзя выбрать; смена технологии на недоступную модель не сохраняется.

Каталог Whisper содержит также экспериментальные GGML-донастройки RU/EN
Code-Switching с фиксированной ревизией экспорта и SHA-256. Признак
`experimental` показывается для загрузки и найденного файла, включая исходное
имя экспорта. `autoSelect` исключает такие модели; явный путь применяется.

`recognitionTechnology` хранит `whisper` либо `fluidaudio`, `fluidModel` —
`nemotron`, `parakeet-tdt-v3`, `parakeet-ultra`, `parakeet-redux` либо `phonon-2.5`.
Выбор Whisper хранится в `whisperModelPath`:
при FluidAudio он задаёт резерв. При чтении JSON с `recognitionEngine` выбор
преобразуется в соответствующую технологию и модель. Новые поля имеют приоритет.

## Локальный HTTP API

`LocalAPIHTTPServer` использует Network.framework и привязан к `127.0.0.1`.
На соединение принимается один HTTP-запрос с Content-Length, ответ закрывает
соединение. Ограничения: 16 КиБ заголовков, 1 МиБ тела, 10 секунд на загрузку,
до 32 соединений. Повторные заголовки, Transfer-Encoding и Origin отклоняются;
multipart разбирается как бинарные данные, имя присланного файла не используется.
`LocalAPIWire` проверяет структуру RIFF/WAV и PCM16/16 кГц/моно.

`LocalAPIService` сериализует API-задачи на main без блокирующего ожидания ASR:
одна активная и восемь ожидающих, deadline 85 секунд от начала HTTP-соединения.
Каждая задача фиксирует сохранённые настройки и ключ выбранного AI-профиля в
начале обработки. Переключатели `apiEnabled` и `apiImproveText` по умолчанию false,
`apiPort` — 8790; сохранение настроек запускает, перестраивает или останавливает
listener. Выход из Runvoice останавливает сервис, пробуждение перепрогревает его.

`apiRecognitionModel` хранит наследование `.application` (значение по умолчанию
для старых настроек), путь Whisper либо идентификатор FluidAudio. Каталог API
использует те же найденные/добавленные Whisper и установленные FluidAudio, что
раздел «Распознавание», с фильтрацией по совместимости. Недокачанные модели не
предлагаются. Выбор проецируется в отдельную копию настроек API, меняя только
технологию и модель; язык, словарь и AI-профиль остаются общими. Профиль диктовки
не изменяется. Недоступный явный выбор не заменяется наследованием: UI сохраняет
отключённый пункт, health и запросы дают 503. Alias `runvoice-active` обозначает
эффективную модель API, health сообщает её технологию и имя.

`apiAudioFilterEnabled` и `apiUseVocabulary` по умолчанию true,
`apiMinimumSpeechDbfs` — −55 (ограничен диапазоном −70…−20). API-проекция
очищает словарь только в копии настроек, когда его использование отключено.
Отдельный CPU-процесс `runvoice-vad` использует штатную GGML Silero-модель,
принимает ограниченный PCM16 через IPC и возвращает JSON-интервалы в отсчётах.
Входы независимы: рекуррентное состояние сбрасывается между запросами.
RMS считается окнами 20 мс; для принятия VAD-интервала требуется 80 мс выше
порога. VAD использует вероятность 0.5, минимальную речь 80 мс и тишину 100 мс.
Сохраняется непрерывный диапазон принятых интервалов с запасом 200 мс с краёв.
Отсутствие речи даёт пустой успешный ответ без ASR/AI; ошибка фильтра даёт 503.
При включённом общем фильтре повторная VAD-обрезка Whisper отключена только
в API-запросе. Фильтр включён в lifecycle, очередь, отмену и deadline API.
Помощник собирается статически для обеих архитектур; модель обязательна при упаковке.

Сохранение только API-параметров использует отдельный callback приложения:
API-поля объединяются с актуальными настройками на диске; остальные поля не
нормализуются и не перезаписываются. Общий callback с обновлением хоткеев/HUD,
прогревом диктовки, а также операции Keychain, автозапуска и истории пропускаются.
Наличие черновых изменений других вкладок переводит сохранение в штатный общий путь.

`APIRecognitionEngine` владеет отдельными от `DictationSession` процессами.
Whisper-server использует внутренний порт 8798, выбранные для API веса, штатные VAD и параметры
полного распознавания; уникальный приватный request-path исключает отправку
аудио другому серверу на занятом порту. GUI Whisper остаётся на порту 8799.
Для FluidAudio создаётся собственный `FluidSpeechClient`: Nemotron получает
PCM и finish, оконные модели — transcribe с временным WAV в state/api/requests.
Модели не скачиваются автоматически; ошибка не переводит API на другой движок.

Смена профиля завершает текущую задачу со старым снимком и готовит выбранный
движок для следующих. Health готов только при живом worker и совпадении профиля
с текущими настройками. При отмене инвалидируются callbacks, останавливается
API-движок и удаляются временные файлы; GUI-сессия остаётся независимой.
Цифровая тишина обрабатывается после проверки готовности без фиктивного текста.

AI-правка использует общий `Settings.dictationFixPrompt` и `AIClient` с
отключённым подробным логированием. Возвращаемая функция отмены закрывает
URLSessionDataTask либо собственный CLI-процесс OpenCode. Оба pipe CLI дренируются
параллельно. Явно переданный снимок ключа, включая пустой, не заменяется более
новым значением из Keychain. Ошибки API возвращаются обобщённо, без тел провайдера.
API не вызывает shell-конвейер вставки, не пишет status диктовки или историю.

## Захват звука

`NativeAudioRecorder` использует входной Audio Unit AUHAL с выключенным выходом.
Устройство выбирается по Core Audio UID; имя используется для настроек без UID.
Один захват обеспечивает WAV, спектр микрофона и данные для распознавания.
Проверка микрофона, диктовка и запись сэмпла используют общий механизм исключения параллельного захвата.

Аудиоколбэк передаёт данные через пул буферов. Файловый I/O и преобразование
через AVAudioConverter выполняются в отдельной очереди. Распознавание получает
PCM16, 16 кГц, моно. WAV записывается во время диктовки; при остановке очередь
и хвост конвертера дренируются до финализации файла.

На паузе Audio Unit останавливается без удаления контекста и без закрытия WAV.
Очередь уже захваченного PCM дренируется до подтверждения паузы, затем новых
данных нет. Продолжение использует тот же ресемплер и файл; длительность паузы
не добавляется в аудио. Оконный preview отменяет промежуточную гипотезу, затем
после дренирования PCM фиксирует размер payload открытого WAV и читает этот
снимок в фоновой очереди, не полагаясь на ещё не обновлённый WAV-заголовок.
Запрос содержит весь снимок до границы паузы, без порога нового аудио и ограничения
окном preview. Для Whisper используются полный `audio_ctx`, beam 5 и дополнительные
0.5 с тишины только в запросе. Успешный полный ответ заменяет хвост стабилизатора
без поиска привязки к прежней гипотезе; дальнейший preview продолжает от него.
При ошибке допускаются до двух повторов через секунду; отмена или новая сессия
отбрасывает старый ответ. Исходный WAV и длительность записи не меняются.
Nemotron завершает отрезок, сохраняет его текст и сбрасывает декодер для следующего
отрезка; worker добавляет сохранённый префикс к частичным и итоговому ответам.
UUID сессии и WAV сохраняются. Часы считают только монотонное активное время.

Состояние сессии и UUID защищают от запоздалых аудио- и сетевых колбэков.
При отмене микрофон освобождается, временное аудио удаляется; распознавание,
AI, вставка и запись в историю не запускаются.

## Локальные аудиосэмплы

`AudioSampleRecorder` использует отдельный `NativeAudioRecorder` с тем же lease
микрофона и выбранным UID. Состояния — подготовка, запись, сохранение и готовность;
повторная остановка не дублирует сохранение. Таймер ограничивает сэмпл 60 секундами,
закрытие модалки или настроек завершает захват и дожидается сохранения. Ошибочная или слишком короткая запись удаляется.
ASR, VAD, постобработка, буфер обмена и история к этому пути не подключены.

`SampleAccessLabel` открывает `AudioSamplePanel` по четвёртому последовательному
клику на номер версии (счётчик кликов AppKit). Окно показано как sheet настроек,
повторный вызов не создаёт вторую модалку. На вкладке «Основные» записи сэмплов нет.
Модалка показывает состояние записи, таймер и `WaveformView`, который получает
PCM через тот же `AudioSpectrumAnalyzer` без распознавания. Остальная обработка
сэмпла остаётся отдельной от диктовки.

Папка по умолчанию — `local-audio-samples/` рядом с исходниками по месту сборки.
Выбор другой папки хранится локально в `UserDefaults` под ключом
`RunvoiceAudioSampleDirectory`; он применяется сразу. Во время захвата и сохранения
смена папки запрещена. Для папки внутри Git добавляется адресное правило
`.gitignore` с экранированием имени; существующие правила сохраняются. Корень
репозитория и `.git` не выбираются. Вне Git дополнительных правил не требуется.
WAV — PCM16/16 кГц/моно без усиления или нормализации. После финализации WAV
в фоновой очереди создаётся JSON с RMS/пиком, процентилями, клиппингом и уровнями
кадров 1024 отсчёта.
Ошибка JSON не удаляет успешно записанный WAV. Папка имеет права 0700,
создаваемые приложением файлы WAV и JSON — 0600.

## Whisper

Статические `whisper-server` и `whisper-cli` входят в приложение.
Сервер держит выбранную модель в памяти и принимает запросы на loopback-адресе.
При запуске, сохранении настроек и пробуждении выполняется фоновый прогрев
на синтетическом аудио. При начале диктовки запрос прогрева отменяется.

Предварительное распознавание использует ограниченный буфер PCM в памяти:

- первый запрос доступен после 0.8 с звука, следующий — после 0.6 с нового аудио;
- окно содержит до 6 с, `audio_ctx=512`, жадное декодирование и отключённые таймкоды;
- таймер проверяет готовность каждые 100 мс; после ответа проверка выполняется сразу;
- одновременно работает один запрос, очередь аудиоснимков не создаётся;
- energy gate пропускает тишину; после речи допускается одно подтверждение хвоста;
- повтор после ошибки разрешён не раньше чем через секунду.

`LivePreviewStabilizer` подтверждает продолжение относительно конца показанного
текста по соседним гипотезам. Ранний первый ответ может быть фрагментом слова;
полное начало восстанавливается после совпадения ответов. Подтверждённые
последующие слова сохраняются. Очистка подавляет пунктуационные петли, маркеры
тишины и повторяющиеся фрагменты. Предпросмотр не является итоговой расшифровкой.

При остановке preview отменяется с закрытием HTTP-соединения. Полный WAV
передаётся в итоговое распознавание; при недоступном сервере используется CLI.

## FluidAudio: Nemotron, Parakeet, Phonon и резервный Whisper

На Apple Silicon помощник `RunvoiceASR` использует
[FluidAudio](https://github.com/FluidInference/FluidAudio) и
[Nemotron 3.5 ASR Streaming Multilingual 0.6B Core ML](https://huggingface.co/FluidInference/Nemotron-3.5-ASR-Streaming-Multilingual-0.6b-CoreML).
Зависимость закреплена в [Package.resolved](../streaming/Package.resolved).
Лицензии FluidAudio и fastcluster включаются в arm64-бандл.
В бандл также включена атрибуция Parakeet: исходные веса NVIDIA — CC BY 4.0,
производные Ultra/Redux — Moondream, Phonon-2.5 — Fermion Research,
преобразования Core ML — FluidInference и Muesli-HQ.

Модель скачивается отдельно: вариант `multilingual/1120ms` содержит русский и
английский. Язык задаёт подсказку декодеру; выбор English не переключает модель
на вариант Latin. Маркер установки создаётся после успешной загрузки Core ML.
Проверка файлов, отмена и повторное скачивание доступны в «Распознавании».

Помощник держит модель в памяти между диктовками. Приложение передаёт команды
и PCM через JSON lines; ответы содержат UUID сессии. Partial обновляет HUD,
`finish` завершает поток. При успешном результате повторный Whisper ASR не нужен.
При падении процесса, пустом результате или таймауте выбранный Whisper обрабатывает
полный резервный WAV. Для такого случая нужна доступная модель Whisper.

### Parakeet TDT v3

[Parakeet TDT v3 0.6B Core ML](https://huggingface.co/FluidInference/parakeet-tdt-0.6b-v3-coreml)
использует `AsrModels` с `.v3` и `AsrManager`. Каталог
`models/parakeet-tdt-v3` отделён от `models/nemotron`; маркер установки появляется
после успешной загрузки моделей. Рабочий процесс читает локальные компоненты,
не скачивая файлы во время диктовки.

Ultra, Redux и Phonon-2.5 используют тот же оконный/финальный конвейер с
соответствующим `AsrModelVersion` и отдельными каталогами. Для Redux энкодер
явно настроен на CPU, чтобы обойти падение GPU/LUT2 в MPSGraph и долгую первую
компиляцию для ANE; для Phonon-2.5 используется GPU согласно политике SDK. Остальные модели
сохраняют размещение вычислений SDK. Выбор не переключается после скачивания.

Для предпросмотра `LiveTranscriber` передаёт PCM помощнику через локальный backend:
первый запрос после 0.8 с, следующие после 0.6 с нового звука, окно до 6 с.
Используются общие стабилизация, energy gate, backoff и один запрос одновременно.
Команда `preview` содержит UUID сессии и запроса; отменённые ответы игнорируются.
Выполняющаяся prediction Core ML может завершиться после отмены, её текст не публикуется.

После остановки команда `transcribe` передаёт путь полного WAV. Менеджер распознаёт
весь файл, используя разбиение для длинных записей. Таймаут полного ASR — 300 с,
потокового хвоста Nemotron — 15 с. Затем используется общий конвейер AI и вставки;
в историю передаётся фактическая модель. При переключении модели FluidAudio
помощник выгружается и прогревает выбранную модель.

## Словарь и постобработка

Словарь хранит до 64 терминов или фраз по 80 символов. Whisper получает
ограниченный UTF-8 prompt, Nemotron — усиление терминов при декодировании,
AI-редактор — предпочтительные написания. Фонетические замены по готовому тексту
не выполняются. Ввод проверяется целиком, без молчаливой обрезки списка.
Parakeet использует словарь только через AI-редактор, отдельный CTC-rescoring не применяется.

Модель, язык и AI-профиль фиксируются на сессию. Настройки предпросмотра можно
применять во время записи. После финального ASR выбранная AI-правка выполняется
последовательно; вариант «Не использовать AI» передаёт распознанный текст напрямую.
API-ключи профилей хранятся в Keychain.

## Расшифровка файлов и саммари

Окно «Расшифровать аудио…» работает отдельно от диктовки. `AudioTranscribeWindow`
принимает файл через диалог или drag & drop, а `DictationRunner` запускает
`dictate.sh transcribe-file` с выбранной моделью Whisper и языком. Скрипт
конвертирует входной файл через `ffmpeg` в PCM16 16 кГц mono и пишет результат
во временный файл; буфер обмена, HUD и история диктовки не затрагиваются.
Отмена завершает процесс и удаляет временные файлы.

В режиме «Саммари» распознанный текст не отправляется в AI автоматически:
генерация начинается по кнопке. Используется провайдер, выбранный для улучшения
текста, и промпт саммари из настроек либо временный промпт окна. Короткий текст
обрабатывается одним запросом. Длинный текст `SummaryService` делит по
предложениям, суммирует части техническим промптом и объединяет результат,
применяя пользовательский промпт к финальному саммари. Исходный транскрипт и
саммари кэшируются в окне; изменение текста или промпта сбрасывает кэш.

Окно показывает фактическую модель Whisper, язык и AI-профиль, а под именем
файла — длительность, размер и формат. В режиме «Саммари» выбор файла и
drag & drop скрыты. Пресеты промпта заполняют поле из готовых формулировок;
результат можно сохранить в `.txt` или `.md`, открыть в TextEdit, найти по
`⌘F` и скопировать. Ошибки оставляют окно и исходный текст на месте и
предлагают повтор операции или открытие `dictate.log`.

## HUD, клавиши и вставка

HUD — nonactivating panel с чёрным скруглённым фоном. Позиция мыши фиксируется
при запуске операции, центральная ось и край привязки сохраняются при росте текста.
Основная карточка пропускает клики; две отдельные панели кнопок слева принимают
клики без смены фокуса. Первая переключает паузу/продолжение через
`DictationSession.togglePause` с UUID текущей сессии независимо от настройки Space,
вторая отменяет диктовку. Круг первой кнопки — 18 pt при области нажатия 22 × 22 pt.
Во время записи внутри красная точка 8 pt и заполненная красная аура.
Её целевой уровень задаёт `RecordingAuraEnvelope`: среднее шести наиболее высоких
полос с порогом 0.04, коэффициентом 2 и ограничением до 0.88. Диапазон подобран
по локальным сэмплам речи без публикации аудио. Дополнительное sqrt-усиление ауры
не применяется. Собственный таймер кнопки сглаживает только ауру с постоянными
времени 100 мс при нарастании и 320 мс при спаде. Наведение не меняет огибающую,
пауза и скрытие HUD останавливают таймер и сбрасывают уровень.
`WaveformView` не содержит таймеров: спектр принимает текущие полосы сразу,
сохраняя исходную нормализацию и sqrt-высоту штрихов. Затухания спектра нет.
Наведение плавно превращает две половины круга в штрихи паузы за 180 мс,
не отключая ауру и не меняя сессию. Обратный переход использует текущую форму,
включая быстрое перемещение курсора. На паузе тот же символ без ауры,
справа «Пауза» вместо спектра; таймер замер, текст дополняется до границы паузы.
Скрытие HUD останавливает таймер перехода и сбрасывает уровень ауры. Хинт запуска — отдельная панель с хвостиком к строке меню.

`HUDTranscriptLayout` ограничивает предпросмотр выбранным числом последних строк.
Служебное `... ` обозначает скрытое начало и участвует в расчёте ширины.
Текст привязки хранится отдельно от маркера; маркер не попадает в финальный результат.

`HotkeyMonitor` использует активный CGEventTap. `DictationKeyPolicy` поглощает
включённые Enter/Esc/Space до отпускания. Enter завершает конкретную запись,
Esc отменяет её, Space переключает запись и паузу; проверка фазы и UUID защищает
новую сессию от отложенного события. Enter/Esc действуют также на паузе.
Флаг паузы по умолчанию включён; его отключение на паузе сохраняет возможность
одного продолжения по Space. Завершение и отмена инвалидируют переходы I/O.
Во время назначения сочетания глобальный обработчик приостановлен.

Финальный JSON передаёт результат из shell в приложение. `DictationPasteboard`
заполняет NSPasteboard и отправляет одну ⌘V. После отправки добавляется история.
Восстановление буфера проверяет changeCount, чтобы не затереть новое копирование.
Если нет Accessibility, текст остаётся доступным для ручной вставки.

## Диагностика и границы ответственности

Аудио распознаётся локально. Выбранному AI-провайдеру отправляется текст и промпт.
WAV и временная расшифровка удаляются после обработки или отмены.
История и логи хранятся локально с приватными правами; распознанный текст может
присутствовать в логах диктовки. Метрики `preview_request_ms`, `preview_stabilize_ms`,
`preview_gap_ms` и `preview_result` не содержат текст или аудио.

GUI не использует FFmpeg для записи. CLI-режим использует FFmpeg → PCM → WAV,
`skhd` и отдельный HUD. Одновременная диктовка через CLI и приложение не поддерживается.

Настройка — в [руководстве](../README.md). Проверки и способы воспроизведения —
в [тест-плане](testing.md). История опубликованных выпусков — в [CHANGELOG](../CHANGELOG.md).

## Обновления приложения

`UpdateCoordinator` отделён от настроек и распознавания. Собственный таймер
вызывает тихий probing Sparkle при запуске, затем через 24 часа после успеха
или через час после ошибки; после пробуждения проверяет срок. Сессии не дублируются.
Доступная версия кэшируется в UserDefaults, сигнализируется отдельным цветным
слоем над шаблонной иконкой. Смена символов записи не удаляет индикатор.
Ручная проверка открывает стандартный интерфейс Sparkle. Снимки и тесты не
запускают сетевой backend.

`RunvoiceUpdateDriver` перехватывает выбор установки готового обновления:
координатор ждёт отсутствия активных операций и допускает отмену ожидания.
Перед продолжением устанавливается барьер новых операций; API отвечает 503.
Delegate Sparkle повторно проверяет допуск перед завершением приложения.
Обработка ошибок освобождает барьер. Штатное завершение останавливает собственные
ASR/VAD-процессы. Модели и данные вне бандла не заменяются.

Sparkle закреплён по версии и SHA-256, встроен в Frameworks. У каждой сборки
своя подписанная лента GitHub Releases. Обязательны EdDSA для appcast и архива,
проверка перед распаковкой; автоматическая установка отключена. Workflow разделяет
сборку/проверки без секрета и подпись в environment release. Секрет преобразуется
во временный файл 0600, соответствие открытому ключу проверяется до подписи.
Процедура публикации и доверия описана в [обновлениях](updates.md).

## FR-001 — Диаризация

**Статус:** `Proposed`, не реализовано. Ориентир приоритета — P2;
срок реализации и движок не определены.

### Ожидаемое поведение

Для записи с несколькими собеседниками определять говорящих и подписывать реплики:

```text
Говорящий 1: Привет, как дела?
Говорящий 2: Хорошо, спасибо. А у тебя?
```

Номера назначаются по первому появлению. При одном говорящем метки не нужны.
AI-постобработка должна сохранять метки и не объединять реплики разных людей.

### Ограничения интеграции

Приложение записывает моно 16 кГц. Встроенная стерео-диаризация Whisper требует
разведения двух говорящих по каналам; она не обеспечивает целевое поведение
обычной моно-записи с несколькими русскоязычными собеседниками.
Нужны отдельное определение говорящих и сопоставление временных сегментов ASR.
Кандидаты и исследовательские оценки зафиксированы в CHANGELOG; выбор реализации
требует отдельной проверки на целевых платформах.

### Критерии готовности

- [ ] Отключаемая настройка диаризации, по умолчанию выключенная.
- [ ] Моно-запись с обычного микрофона, русский язык.
- [ ] Как минимум 2–4 говорящих, нумерация по первому появлению.
- [ ] Один говорящий — без меток; доступен автоматический и ручной выбор количества.
- [ ] AI-промпт сохраняет номера и границы реплик, не придумывает говорящих.
- [ ] Модели загружаются отдельно и проверяются по SHA-256.
- [ ] Работа на macOS 15+ с Apple Silicon и Intel.
- [ ] Обычная диктовка работает при выключенной настройке.
- [ ] В [тест-плане](testing.md) есть моно/стерео, один/несколько говорящих,
      пересечения речи, ошибки движка и отмена обработки.

### Риски и открытые вопросы

- Выбор движка, лицензий, моделей и размера загрузки.
- Задержка дополнительной обработки и расход памяти на обеих архитектурах.
- Ошибки кластеризации при шуме и одновременной речи.
- Надёжность автоматического определения числа говорящих.

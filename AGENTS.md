# AGENTS.md — правила работы над Runvoice

## Язык и стиль

- Общение с пользователем и документация — на русском.
- Не менять код без явного подтверждения, если пользователь просит сначала
  проанализировать или предложить план.
- Держать изменения в рамках задачи; не делать попутных рефакторингов.

## Обязательное правило: актуальная документация и история

- Все Markdown-файлы проекта описывают только действующее поведение,
  архитектуру, ограничения, инструкции и процедуры проверки.
- **Единственный журнал изменений — `CHANGELOG.md`.** Только в нём хранятся
  номера выпусков Runvoice, история реализации, сравнения между выпусками,
  датированные отчёты проверок, результаты установок и исторические замеры.
- В README, тест-плане, архитектуре, бэклоге и каталоге скриншотов не вести
  хронологию, не добавлять разделы по выпускам и не указывать конкретные номера
  Runvoice, включая номер текущей сборки. Ссылаться на CHANGELOG без пересказа.
- При изменении кода или документации добавлять запись в раздел «Не выпущено»
  CHANGELOG. При выпуске переносить её в раздел с номером из `app/Info.plist`.
  Даты указывать только при наличии подтверждения; даты замеров отделять от дат выпуска.
- Описания функций и тестовые сценарии обновлять на месте, по тематическим
  разделам. Устаревшие ожидания заменять актуальными; исторические материалы
  переносить в CHANGELOG с сохранением фактов и результатов.
- В бэклоге оставлять только нерешённые задачи с текущим статусом. Выполненные
  и отклонённые задачи удалять из бэклога; историю решения хранить в CHANGELOG.
- Версии macOS, Swift, зависимостей и точные имена моделей допустимы как
  актуальные технические требования. Номера Runvoice в путях и командах получать
  из метаданных сборки либо обозначать понятным шаблоном без конкретного числа.
- История распознаваний, данные предыдущей сессии и восстановление буфера —
  действующие функции, их описание не является журналом изменений проекта.
- Перед завершением проверять все Markdown-файлы проекта: актуальность по коду,
  отсутствие истории и номеров Runvoice вне CHANGELOG, локальные ссылки,
  якоря и изображения. Зависимости и сгенерированные каталоги не редактировать.

## Обязательное правило: тестовые сценарии

**При любом изменении функционала обновляй `docs/testing.md`.**

Это касается:

- новых и изменённых настроек и вкладок;
- хоткеев, HUD, диктовки, вставки;
- менеджера моделей, скачивания, прогрева сервера;
- режимов постобработки, промпта, Keychain;
- установки, DMG, архитектур, разрешений;
- исправлений багов, которые должны быть покрыты регрессией.

Если меняется UI, дополнительно обновляй `README.md` и скриншоты в
`docs/screenshots/`.

## Сборка и проверки

```sh
bash -n bin/dictate.sh
scripts/build-app.sh     # две архитектуры: arm64 и Intel
make dmg                 # два DMG + .sha256
```

Минимальные проверки перед коммитом:

- приложение собирается для arm64 и x86_64;
- `codesign --verify --deep --strict` проходит для обеих архитектур;
- DMG создаются и проходят `hdiutil verify`;
- smoke-набор из `docs/testing.md` выполнен на текущей машине;
- `--snapshot-states` и `--snapshot` не падают;
- `git status` чистый после коммита.

## Архитектура и упаковка

- Две отдельные сборки: `Runvoice-arm64.app` (Apple Silicon, Metal) и
  `Runvoice-intel.app` (Intel, Whisper на CPU).
- `dist/Runvoice.app` — копия для текущей машины (host).
- Модели Whisper в бандл не входят; VAD-модель входит.
- `whisper-server`/`whisper-cli` — статические, без Homebrew.
- Минимальная macOS — 15.0.

## Важные особенности

- Хоткей должен применяться сразу после сохранения, без перезапуска.
- HUD не забирает фокус; ⌘V отправляет само приложение.
- Постобработка: `OpenCode` / `Свой API` / `Без правки`; при «Без правки»
  промпт скрыт.
- API-ключ хранится в Keychain и не попадает в логи/`settings.json`.
- После сохранения настроек сервер прогревается в фоне.
- Для локальной подписи используется сертификат `Runvoice Local Signing`
  или `RUNVOICE_SIGN_IDENTITY`; без доступного сертификата сборщик применяет
  ad-hoc-подпись приложения. Для внешнего распространения нужны Developer ID
  и нотаризация.
